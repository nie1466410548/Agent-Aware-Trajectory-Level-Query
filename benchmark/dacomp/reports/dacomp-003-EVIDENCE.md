**本题结论：没有发现值得单独构建 SQL MV 来覆盖多条后续 SQL 的候选，因为 Q2 后根本没有 SQL。已有 Join 结果确实服务了后续多段 Python 分析。这支持“分析任务可复杂，但 SQL 轨迹仍短”，不支持“多条 SQL 重复执行同一 Join”。**

两条 SQL 执行并取回总共约 2.9 ms。SQL 层未发现下钻、上卷或结果值进入后续 SQL 谓词；Python 中有子群、平行维度和结果依赖。不能把这些 Python 现象直接换算成 SQL 物化收益。
