# 九题快速验证：修订后的结论

已完成 Kimi 的 9 个任务 × 自然/FAD 两组，共 18 次运行。两组均有 7/9 题通过原始验证器。原始 SQL、工具结果、消息和 Python 脚本保留。

## 多查询优化机会

本轮重新按任务审阅 SQL，不再把同表重访、相同 COUNT(*) 或 Join 文本片段的频率当作优化机会。

| 口径 | 自然组 | FAD 组 |
|---|---:|---:|
| 公共准备对象候选 A | 5 | 6 |
| 涉及任务 | 5/9 | 5/9 |
| 涉及成功数据调用（含部分子计算受益） | 20/65（30.8%） | 15/42（35.7%） |
| 首次使用后仍有至少两次使用的 A 候选 | 4 | 3 |
| 较弱的扫描统计准备候选 B | 3 | 1 |

自然组的公共对象主要是出版年份提取、文学类别筛选、Owner Assignment 历史子集、原始键 Opportunity–Contract Join、订单时间窗口及明细 Join。FAD 组还有归一化连接键、重复股票日期解析和需要保留 LAG 前驱行的共同窗口。

这些是人工审阅得到的、有具体共同对象与消费者的候选，不是已证明的加速或穷尽枚举。覆盖率不表示整条 SQL 都可以省略，更不表示成本节省比例。使用完整轨迹事后选出的对象能否在当时通过 FAD 提前识别尚未检验。本轮没有重跑 Agent，没有实施物化/索引，也没有性能实验。

详见 [重写的 OVERLAP 报告](OVERLAP.md)、[逐候选与 SQL 证据](OPPORTUNITY_CASES.md)、[机器可读清单](opportunities.json)。

## FAD 实验目前支持什么

FAD 组通过提示和回执协议要求 Agent 在 SQL 前提交意图，改变了 Agent 行为；不是自然轨迹的被动未来预测。45 次回执时序检查均通过，42 个数据目标的下一步表精度为 98.4%、覆盖率为 100%。仅 17 个显式远期前瞻点的第 2/3 条表集合精度为 82.4%，任务差异明显。

数据 SQL 调用由自然组 66 次变为 FAD 组 42 次，但新增 45 次 FAD 提交，可见 assistant 消息由 103 增至 162。每题每组只跑一次，两组是不同随机轨迹，不能推断协议的因果收益。FAD 到 SQL 的中位时间差 8.27 秒包含协议引入的模型/工具开销，不是免费的物化时间。

## 审计说明

此前所说的 146 条 SQL，更准确地说是 146 次含 SQL 的工具调用及对应导出文件，其中含元数据。成功数据调用为自然组 65、FAD 组 42，分别包含 66、44 条 SQL 语句；3 次调用各含两条语句，适配器只保存其末条结果。失败尝试及全部原始文本保留。

任务按描述预先选择，非随机总体样本；通过原始验证器不等于完整独立正确性证明。31 张已准备表共 135,492 行，属于小规模实验。部分机会来自最终答题失败的探索轨迹，报告保留这些标记。
